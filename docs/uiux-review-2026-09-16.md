## 1. 優先して直す5件

### ① 教材一覧に「探す」「すぐ始める」が無い（最優先）

**対応済み（コミットID: [a1ec037](https://github.com/gangbenguiren13-ai/wordcards/commit/a1ec037fe374a52b42346097d80164cdec555782)、main反映済み）**。検証・公開状況は [実装記録](uiux-implementation-2026-09-17.md) を参照。

- **対象**: 教材一覧（T2 Home）。区分B・要確認
- **現在**: 更新日順のカードが並ぶだけ。検索・絞り込み・並べ替えの手段がない。各カードの主ボタンは「ひらく」（編集画面へ）で、ゲームを始めるには **ひらく → 編集画面を最下部まで送る → ▶ゲームをはじめる → ゲームを選ぶ → 設定 → はじめる** の6手順
- **困る場面**: 87セットになった今、授業開始直後にスクロールして探す。生徒が待つ。編集画面を経由するので、授業中に誤ってカードを触るリスクもある
- **改善案**:
  - 一覧の最上部に**検索欄**（セット名の部分一致。ひらがな・英語どちらでも）を常設。入力と同時に絞り込む
  - 各カードに **「▶ あそぶ」を主ボタン**として置き、直接ゲーム選択へ。「ひらく（編集）」は副ボタンに格下げ
  - **「最近使った」を先頭3件**に固定表示（localStorageで端末ごとに記憶。サーバー変更なし）
  - セットに**タグ（学年・単元）**を持たせて絞り込みチップを出す。DB変更が要るので第2段階でもよいが、87セットなら検索だけでも劇的に楽になる
  - 「削除」はカード上の常設ボタンから外し、「…」メニューの中へ（主操作の隣に赤いボタンがある状態を解消）
- **優先度**: 最高 ／ **変更の大きさ**: 中（検索と最近使ったは1画面で完結。タグはDB追加）
- **確認**: 87セットの中から目的のセットを**10秒以内・3タップ以内**でゲーム開始できる。一覧から削除を誤タップできない

### ② ゲーム開始前の設定が毎回フルサイズで出る

**対応済み（コミットID: [b934331](https://github.com/gangbenguiren13-ai/wordcards/commit/b93433183bddd74ff438268f95d25c4f665ddf82)、main反映済み）**。検証・公開状況は [実装記録](uiux-implementation-2026-09-17.md) を参照。

- **対象**: ゲーム設定（T8 GamePlay）。区分B・要確認
- **現在**: 出す順番・送り方・秒数・復習方式・進捗表示・音声・声の選択が、毎回すべて展開された状態で表示される。前回設定は記憶されるが、画面は同じ長さ
- **困る場面**: 2回目以降の授業でも毎回スクロールして「はじめる」に届く。iPad縦向きだと設定が画面2枚分になる
- **改善案**:
  - 最上部に **「前回と同じ設定ではじめる（N枚）」** の大ボタン。設定の要約を1行で添える（例: 「ランダム・手で送る・ふくしゅうを混ぜる・音あり」）
  - その下に「設定を変える ▾」で折りたたみ。初回だけ展開
  - 声の選択は「音声」の中に畳む（ほぼ1回しか触らない）
- **優先度**: 高 ／ **変更の大きさ**: 小（既存の設定記憶をそのまま使う）
- **確認**: 2回目以降は画面を送らずに「はじめる」が押せる。設定を変えたいときは1タップで全部見える

### ③ 生徒用エラー画面の文言が誤解を生む（実際に確認済み）

**対応済み（コミットID: [52f562e](https://github.com/gangbenguiren13-ai/wordcards/commit/52f562e14798c1d11341b8fc6811dd602c11c1ef)、main反映済み）**。検証・公開状況は [実装記録](uiux-implementation-2026-09-17.md) を参照。

- **対象**: 生徒用ランディング `/p/…` のエラー状態。区分A
- **現在**: 無効なURL（削除済み・共有オフ・打ち間違い）を開くと「よみこめませんでした。通信を たしかめて、もういちど。」＋「もういちど よみこむ」ボタン。**通信の問題ではないのに通信を疑わせる**
- **困る場面**: 生徒が「Wi-Fiが悪い」と思って何度も再読み込みし、先生が呼ばれる。原因（QRが古い／共有がオフ）に気づけない
- **改善案**: 応答の種類で文言を分ける
  - 404（URL無効・共有オフ）: 「**このQRコードは つかえません。先生に みせてください。**」ボタンなし（再読み込みしても直らない）
  - 通信失敗（オフライン・タイムアウト）: 現行の「通信を たしかめて、もういちど」＋再読み込みボタン
  - 教師側の共有モーダルに「共有をオフにすると、生徒には『このQRコードはつかえません』と表示されます」と添えると、先生が状況を説明できる
- **優先度**: 高 ／ **変更の大きさ**: 小（`NOT_FOUND` と `NETWORK` の分岐を1つ足す）
- **確認**: 無効なURLで再読み込みボタンが出ない。機内モードでは再読み込みボタンが出る

### ④ 大型画面での文字サイズと、カード送りの当たり判定

**対応済み（コミットID: [b10fd0f](https://github.com/gangbenguiren13-ai/wordcards/commit/b10fd0f411cd33f16029208ca64be0f7de8a0527)、main反映済み）**。検証・公開状況は [実装記録](uiux-implementation-2026-09-17.md) を参照。

- **対象**: フラッシュカード本体。区分B・要確認
- **現在**: 画像＋単語のとき単語は `text-4xl〜5xl`（約36〜48px）。カードの左30%＝前、右70%＝次、表裏モードのみ中央40%＝めくる。ヘッダーの「← やめる」「🔊 音あり」は通常サイズ
- **困る場面**: 教室後方（6〜8m）から48pxの単語は読めない。左右の当たり判定は見えないので、生徒が「戻したいのに進む」を起こす。「やめる」がカード送りの視線上にあり誤タップで抜ける
- **改善案**:
  - 単語の最小サイズを **画面高さの12%**（iPad横で約90px、大型画面で150px超）に。長い語は自動縮小
  - **「画面モード」切替**（教室用／手元用）を設定に置き、教室用は余白を増やし文字を最大化、操作ボタンは下部に集約
  - 左右の当たり判定を**画面端の帯として薄く可視化**（矢印アイコンを半透明で常時表示）。中央タップは常に「次へ」に統一し、めくりは専用ボタンのみ
  - 「やめる」は長押し（0.5秒）で反応、または確認ダイアログを維持
- **優先度**: 高 ／ **変更の大きさ**: 中
- **確認**: 6m離れて単語が読める。生徒の連続タップで「戻る」が誤発火しない

### ⑤ 状態の伝え方が画面ごとにバラバラ

**対応済み（コミットID: [8aa1ff5](https://github.com/gangbenguiren13-ai/wordcards/commit/8aa1ff5a30dea3a941c32b0b136d07f9b4328bb9)、main反映済み）**。検証・公開状況は [実装記録](uiux-implementation-2026-09-17.md) を参照。

- **対象**: 通知・保存表示・読み込み・空の状態。区分A/B
- **現在**: 保存は画面下トースト「保存しました」、失敗は赤トースト、読み込みはスピナーと進捗バーの2種、空の状態は一覧にのみ。警告は編集画面上部の赤/黄パネル。**場所も形も4種類ある**
- **困る場面**: 先生が「いま保存されたのか」「エラーなのか警告なのか」を毎回判断する。授業中に赤いトーストが出ると生徒が動揺する
- **改善案**: §2の「状態表示の方針」に統一。要点は、(a) **成功は静かに（ヘッダー右端に「保存済み ✓」が1.5秒）**、(b) **失敗は必ず操作の近くに残る**（消えない。閉じるまで表示）、(c) 読み込みは常に「何を何枚」を出す、(d) ゲーム中の通知は**教師roleのみ**に出し、生徒画面には出さない
- **優先度**: 中 ／ **変更の大きさ**: 中（トースト基盤はあるので出し分けの追加）
- **確認**: 通信を切って操作→エラーが消えずに残る。ゲーム中に通知が生徒画面に出ない

## 2. アプリ全体で統一する方針

いまのトークン（`src/styles/index.css` の `@theme`）を土台に、足りない決まりを足す。

### 色

| 役割 | 色 | 使いどころ |
|---|---|---|
| 主操作 | `brand-600` `#1d4ed8` | 画面に**1つだけ**。「はじめる」「つぎへ」「あそぶ」 |
| 副操作 | 白地＋`line`枠 | 戻る・設定・複製 |
| 危険 | `danger` 赤 | **常設ボタンにしない**。メニュー内か確認ダイアログ内のみ |
| 成功 | `ok` 緑 | 保存済み・正解 |
| 注意 | `warn` 黄 | 要復習★・警告パネル |
| 生徒用アクセント | `#f59e0b`（暖色） | 生徒画面の主操作。教師画面の青と**画面で見分けられる**ようにする |

色だけで意味を伝えない（記号＋文字を必ず併用）は現状どおり維持。

### 文字サイズ（最小値）

| 場面 | 最小 |
|---|---|
| 教師の管理画面 本文 | 16px |
| ボタンのラベル | 16px（主操作は18px） |
| 生徒画面のボタン | 20px |
| ゲーム中の単語（手元用） | 画面高の8% |
| ゲーム中の単語（教室用） | 画面高の12% |
| 進捗「3／10」 | 20px、教室用は28px |

### 余白・タップ領域

- タップ領域: 管理画面 44px、生徒画面とゲーム中 **64px**（現状の方針を維持）
- ゲーム画面の外周に **16px の安全余白**（iPadの画面端誤タップ対策）
- ボタン同士の間隔は最低 12px。主操作と危険操作は同じ行に置かない

### ボタン

- 形は角丸12px・2px枠で統一（現状）
- **ラベルは「動詞＋対象」**: 「はじめる」「つぎへ」「ゴミ箱に入れる」。「OK」「はい」は使わない
- アイコンは絵文字でよいが、**同じ意味に同じ絵文字**（音=🔊、復習=★、開始=▶）。一覧表を `docs/` に置く
- 生徒画面は**ひらがな主体**（現状どおり）。教師画面は漢字を使ってよいが、**同じ機能に同じ語**（例: 「復習」と「ふくしゅう」が混在しないよう、教師画面は「復習」に統一）

### 状態表示

| 状態 | 出し方 | 消え方 |
|---|---|---|
| 保存成功 | ヘッダー右端に「✓ 保存済み」 | 1.5秒で消える |
| 失敗 | 操作したボタンの直下に赤帯＋「もう一度」 | 消えない（閉じるまで） |
| 読み込み中 | 「よみこみちゅう 12／20」進捗バー。3秒超えたら「時間がかかっています」を追加 | 完了で消える |
| 空の状態 | イラスト＋1文＋次の行動ボタン（現状の一覧と同じ型を全画面に） | — |
| 警告（教材の不備） | 編集画面上部パネル（現状）。ゲーム開始画面でも同文言 | 直すまで残る |
| ゲーム中の通知 | **教師roleのみ**。生徒画面には出さない | 3秒 |

### モチベーション（要望への提案）

装飾ではなく「できたことが見える」設計にする。

- **終了画面の演出**: ★ゼロで達成したときだけ、紙吹雪（CSSのみ・1.5秒・軽量）。毎回出すと効かなくなる
- **その日の記録（端末内のみ）**: 「今日 3セット・42枚」を教材一覧の上に小さく。個人情報を保存しない範囲（サーバーには送らない）
- **クラスの記録**: 神経衰弱の「かかった時間」を、そのセットの端末内ベストとして表示。「前回より速い！」の一言
- **教師向け**: 教材一覧に「今週使った回数」の小さな表示（端末内カウント）。作った教材が使われている実感が続ける動機になる

## 4. 良い点・残すべき点

- **失敗が必ず画面に出る仕組み**（全ミューテーションの失敗をトーストに流す）。無反応が最も困るので、この土台は崩さない
- **先読み（プリロード）と進捗バー**。授業中の通信断に強い設計は残す
- **小学校モードで英単語を出さない強制**（設定に何が入っていても画像のみ）。要件の核
- **要復習の2方式と★の1タップ**。授業のテンポを壊さない
- **エラー／警告の2段階**と、色＋記号＋文字の併用
- **生徒画面のひらがな主体**の文言。ただし教師画面との語の統一は§2で
- 装飾を抑えた白基調。大型画面で映える。これを土台に「教室モード」で余白と文字だけ大きくする
