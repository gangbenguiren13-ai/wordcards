# 一括登録と教材ファイルの入出力（P5）

## 使い方

- 教材の編集画面 → **一括登録**。単語を1行ずつ貼り付けるか、表の「空の行を追加」で連続入力する。
- **CSV・TSV** → ファイルを選択。UTF-8（BOM可）とShift_JISを自動判定。サンプルCSVを画面から保存できる。
- **画像・音声をまとめて追加** → ファイル選択またはドロップ。画像・音声の対応を一覧で確認して **確認した内容を登録**。
- 未対応ファイルは「種類」「対応する単語」を指定する。単語が未作成なら **ファイル名から単語を追加して対応づける**。関連画像にも対応。
- エラー行は修正するかチェックを外す。単語の重複・画像なしは警告。既存カードの画像・音声を自動で置き換えず、手動指定した変更は登録前に表示する。
- 教材の編集画面またはホーム → **書き出し** → **ZIPを用意する** → **ファイルを保存**。復元はホーム → **教材ファイルを読み込む（JSON・ZIP）**。
- ZIPには設定・単語・画像・関連画像・音声を同梱する。JSON単体の書き出しは設定・単語のみ。JSONにメディア参照がある場合は、メディアなしで復元することを画面で確認する。

## 表の形式

CSV／TSVは1行目に `word` が必要。任意列は `image_file`, `pair_image_file`, `audio_file`, `sort_order`。列順不問、未知列は無視。引用符で囲んだカンマ・改行・二重引用符に対応。
`sort_order` で並べた後、既存カードの末尾へ追加する。既存カードの単語や順序は変更しない。

自動対応はCSVで明示したファイル名を優先し、指定がなければ既存の正規化規則で単語と完全一致。次に末尾の ` (1)` / `_01` などだけを除去して照合する。`dog2.jpg` を `dog` に寄せない。候補ファイル・単語が複数ある場合は手動対応へ残す。

## 形式と上限

- JSON/ZIPはデータ仕様v1の `wordcards-set` / `formatVersion: 1`。ZIPは `set.json` と `media/`。
- 最大200枚、120枚超は注意表示。画像1個10MB、音声1個2MB、CSV/JSON2MB。
- 一括ファイルは合計600個・100MBまで。ZIPは圧縮前後とも100MBまで。端末メモリを圧迫しないよう、超える教材は分割する。
- 画像は既存のWebP圧縮処理を使用。ZIPから戻すWebPは復号検査後に元のバイト列を保存し、再圧縮による画質劣化を避ける。
- HEIC/HEIFの読み取りは端末の対応に依存する。読めない画像はエラーとして表示するため、JPEG/PNGで再選択する。

## 保存・復旧

登録前の内容は画面内に保持する。登録ボタンを押すまで送信しない。途中の通信エラーは表示し、**同じ画面の「続きから再試行」**で再開できる。安定したUUID・重複しないINSERT・各保存ステップの記録により、応答だけ失われてもカードや復元先教材を二重作成しない。ページを閉じると未完了の作業情報は消える。完了分は教材に残るので、閉じた場合は編集画面で確認し、足りない分を追加する。

復元は新規教材のみ。共有はオフ、共有トークンは空、所有者とカードIDは新規発行。既存教材を上書き復元しない。差し替えメディアは操作ごとの別パスへアップロードし、成功してからDB参照を更新する。古いファイルは直ちに削除しない（途中失敗でも既存教材の参照を維持）。教材をゴミ箱から完全削除する既存処理がフォルダ全体を回収する。

書き出しは所有者ID・DBのID・共有トークン・署名URLを含めない。メディア操作は `mediaStore.ts` 経由の非公開ストレージ。アーカイブのURL参照・相対パスの逸脱・未知形式・上限超・欠けたZIPを拒否する。展開後の実バイト数も計測する。生徒データは扱わない。

## 実装と検証

DB変更：なし。サーバー関数の変更：なし。新規ワークフロー：なし。

新しいDB操作は `src/api/transfer.ts` の教材upsert、カードupsert、メディア参照update。タイトル1〜60文字、単語0〜50文字、カード順序はPostgres整数内、モード・表示方法は既存列の値、所有者はログイン中ユーザー。既存のRLS・CHECK・NOT NULLと照合済み。UPDATE対象が消えていた場合もエラーにする。

追加依存はPapa Parse 5.5.3、fflate 0.8.3（型定義を含む）。既存依存のバージョン変更なし。[Papa Parse公式資料](https://www.papaparse.com/docs)、[fflate公式資料](https://github.com/101arrowz/fflate)を参照。

型検査・lint・ビルド・既存ゲームを含む自動テストに加え、模擬サーバーでCSV→画像・関連画像・音声の対応→通信失敗→再試行→ZIP保存→新しい教材への復元をブラウザで確認する。本番の教師ログイン後の保存と、学校iPadのファイル選択・保存は実機確認が必要。
